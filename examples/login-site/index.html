Keybound login demo

A normal session cookie identifies the login. A separate Keybound device cookie selects the enrolled public key. A browser private key signs a fresh challenge before the protected action runs.

Flow

1. Login

Browser creates a nonextractable P-256 key and sends only the public key.

2. Link

Server stores session, device ID, and public key as one record.

3. Challenge

Server issues a short challenge for a server purpose.

4. Proof

Browser signs. Server verifies and consumes the challenge once.
